# REVIEW — shell-nl-hook

压缩路径的 `6-review`：功能轮 + 质量轮（含安全），UI 轮不适用（无界面）。

## 1. 功能轮

| 项 | 结论 | 证据 |
|---|---|---|
| "不用敲 nlsh"是否真做到 | ✅ 新终端直接输入中文即被接管 | `bash -ic '列出当前目录'` 实跑 |
| 真命令是否零影响 | ✅ 钩子只在命令不存在时被 bash 调用 | AC-3、AC-2a |
| 是否绕过既有安全链路 | ✅ 未绕过：确认门/权限/快照/审计全在 `nlsh -c` 内 | 真机确认门测试（EOF 取消，目录未创建） |
| 可逆 | ✅ 卸载 = 摘标记块；首次写入有备份 `~/.bashrc.bak.nl-os` | AC-5f/5g，真机存在备份 |

**功能轮结论**：通过。

## 2. 质量轮（含安全）

| # | 项 | 结论 |
|---|---|---|
| Q1 | 钩子是否 eval / 自行解析自然语言 | ❌→✅ 设计上就没有 eval；AC-7 用含 `;` 的哨兵证明一字节未执行，整行原样传给 nlsh |
| Q2 | 是否可能把拼错的英文命令交给模型"猜" | ✅ 默认不接管（纯 ASCII 直接走系统 command-not-found）；`git statsu` 这类**根本到不了钩子**（git 存在，由 git 自己报错） |
| Q3 | 是否覆盖了系统的 `command_not_found_handle` 并改变其行为 | ✅ 等价回退（`/usr/lib/command-not-found`，无则 `rc=127`）；AC-6 固定 `/etc/bash.bashrc` 未被改 |
| Q4 | 标记块是否可能重复累加 / 吃掉别人的配置 | ✅ 先摘旧块再写；AC-5d/5e/5g 固定"一段块 + 其它行逐字节保留" |
| Q5 | 含 `/` 的输入 | ⚠️ bash 对含 `/` 的命令名**不触发**钩子 → 这类输入走系统"无此文件"，不会被接管。已写入 TASK §实现中撞到 |
| Q6 | 每次输入的成本 | ⚠️ 规则命中 ≈10ms/19MB；规则未命中仍 1.9s/677MB（冷启动模型）。留给"模型常驻"独立 change |
| Q7 | 无 nlsh 的环境 | ✅ `command -v nlsh` 守卫，缺失时退化为系统行为 |

**质量轮结论**：通过，附两条已知边界（Q5/Q6）。

## 3. 测试自己抓出来的缺陷（已修）

| # | 缺陷 | 怎么被抓到 | 修法 |
|---|---|---|---|
| B1 | `case` 里 `[! -~]` 语法错误（空格未转义），钩子整个 source 失败 | AC-8a `bash -n` 直接红 | 改 `[!\ -~]`，并加注释说明为何不能用 `[![:print:]]`（UTF-8 下中文算 printable） |
| B2 | AC-4b 断言前提错：`git statsu` 压根不会触发钩子 | 手工复现发现 `git` 存在 | 换成真正不存在的 ASCII 命令；并把"git 子命令拼错到不了钩子"写进断言名 |
| B3 | AC-7 哨兵用了绝对路径，命令名含 `/` → 钩子不触发，测试假绿（7a 通过但 7b 红） | 7b 红 | 改相对哨兵名；并把该 bash 行为记进 TASK |

> B3 值得记一笔：**如果只有 7a（"没被执行"）这条断言，B3 会以"通过"的形式骗过测试。**
> 正是那条"整行是否原样传入"的正向断言把它揪出来的。

## 4. 残余风险

1. 用户可能误以为 `cd` 生效（文档已写明；v2 议题）。
2. 规则未命中时 1.9s 冷启动在交互式使用里可感知（模型常驻 change）。
3. 未在 zsh / 其它 shell 验证（本机无 zsh，不假装支持）。
