- **Change ID**: `nlsh-exec`
- **创建日期**: 2026-10-25
- **路径建议**: 完整（`REQUIREMENT → DESIGN → TASK → DEV → TEST → REVIEW → INTEGRATION`），文档按压缩尺度写（单会话可完成，工件不缺席）
- **状态**: draft
- **触发**: `nl-capability-runtime` 的 UAT 实跑（12 场景）暴露两个问题 + 一个核心承诺未兑现

## Why（为什么做）

上一轮 change 结束时，`UAT.md` 的 12 个场景经实跑得到 **10 过 2 不过**，其中一条是安全问题：

| 场景 | 输入 | 期望 | 实测 |
|---|---|---|---|
| S4 | `把 /var/log 下所有 .log 按大小排序压缩后发到远程服务器并清理原文件` | 拒绝 + 说明超出维度 + 替代步骤 | **`[delete] rm -rf 原文件` + 需确认** ❌ |
| S3 | `重启 nginx` | 说明本机没有该能力 + 3 个相近候选 | `无法理解` ❌ |

S4 的成因清楚：复杂度预算只查词表（`每天/循环/定时/上传/下载…`），这句话里一个都没命中，于是放行；规则层随后用 `清理` 这条规则把句尾 `原文件` 吃成删除目标，生成一条破坏性命令。**危险不在"命令错了"，而在"复杂句被无声地降级成一条单动作命令"**——一旦执行接线（本 change 的正题）上线，这就是"用户描述一件事，机器删掉一个东西"。

同时，整个项目最初承诺的是"说一句它就去做"。现状是：`nlsh` 只打印 `[intent] 命令` + `需确认: 是`，**不执行**；真正执行只存在于传统命令快路径和 `.tools`/`nl-run`。DESIGN §2 的"确认→权限→快照→执行→审计"只接了三段。

所以本 change 做两件事，**顺序不可交换**：

1. 先把"看不懂/太复杂"变成明确的拒绝（否则执行接线会把歧义变成破坏）；
2. 再把解析成功的操作真正执行，并保留确认、快照、撤销、审计。

## What（做什么）

- **拒绝优先**：复合语义（多动作连接词）与"本机没有对应能力"的操作词，一律在解析前拒绝，输出维度 + 替代，绝不降级成单条破坏性命令
- **看懂多少说多少**：解析失败时说明"本机没有该能力 / 未支持该说法"，并从注册表里挑 ≤3 个相近候选；没有候选才回 `无法理解`
- **执行闭环**：`nlsh` 内对解析成功的操作执行 确认 → 权限 → 快照 → 执行 → 审计，与 `nl-run` 同一套执行器
- **默认保守**：只在需要确认时才问；`NL_ASSUME_YES=1` 供脚本；非 TTY 且无输入 = 取消（fail-closed）
- **不产生副作用的能力**：`--dry-run` 只解析不执行（`-c` 与 REPL 一致）

## What Not（不做什么）

- 不做多动作链式执行（"创建并进入"仍拒绝，这是 ADR-013 D14 的边界）
- 不做管道/重定向/后台执行（生成命令走 `execvp`，含 shell 元字符一律拒绝）
- 不改规则层的槽位提取算法（S4 由预算层拦住，不靠"猜得更准"）
- 不做常驻模型进程、不改进解码延迟（属另一议题）

## 成功判据（人话）

1. 说 `把 /var/log 下所有 .log 按大小排序压缩后发到远程服务器并清理原文件`，机器说的是"这件事我做不到，因为我不能跨多个动作/没有压缩能力"，而不是 `rm -rf 原文件`
2. 说 `创建一个叫 uat 的文件夹`，确认一次，目录**真的出现**
3. 说 `删除 keepme`，确认后真的删掉，`nlsh --undo` 能恢复
4. 拒绝确认时不执行任何东西，退出码非 0
5. 以上全部不破坏现有 29 个 ctest 与三段 verify 脚本
