# CHANGE — decision-fallback：规则未命中不再干等 20 秒模型

- **Change-ID**: `decision-fallback`
- **提出/完成**: 2026-10-25
- **模式**: ponytail full；压缩路径（0→3→4→6）
- **前置**: `nl-shell-runtime`（常驻进程 + cd）、ADR-012/013（注册表 + 决策层）

## 1. 为什么

上一轮交付时发现：常驻进程省掉了模型**加载**（1.8s），但**推理本身**要 20–30s，
而且对绝大多数输入返回"无法理解"。也就是说 `nlsh` 的"规则未命中"这条路实际不可用。

同时项目里已经有一条毫秒级的**决策层**（候选收缩 + 受约束 Choice，`--decide` 用着），
但它只回答"这是哪个工具"，不回答"用什么参数"，所以一直没接进 `nlsh -c`。

## 2. 目标

规则未命中的常见问句（查目录/磁盘/内存/进程/端口/系统信息…）**不加载模型**就能执行；
认不出的仍然如实拒绝——不许为了"看起来聪明"去猜参数。

## 3. 范围边界

### In

- ADR-022：`dispatch` 的解析链插入**决策层兜底**（规则 → 决策 → 常驻 → 本地模型）
- 一张**10 条、逐条审查过**的只读默认参数表（`READ_DEFAULTS`），只对 L1 能力生效
- `decision.c` 同义词词典扩充 + 权重（特指 10 / 泛指 6），修"`显示当前工作目录` 候选打平"
- `NlSource` 增 `NL_SOURCE_DECISION`，审计与调试可区分三种来源

### Out（登记）

| 不做 | 理由 |
|---|---|
| 让模型输出"工具+参数" | 需二次解码且参数不可信，等于把注入面交给模型 |
| 放宽 `ss`/`netstat` 到 L1 | 权限表是唯一权威，兜底机制无权改权限策略 |
| 表外工具无参数调用 | `grep`/`du` 会等 stdin 或行为不可预期 |
| 让推理本身变快 | 模型层瓶颈，需换路径（候选集受约束解码）或换模型 |

## 4. 最小需求与 AC（压缩路径豁免声明）

- **AC-24 认出即执行**：`显示当前工作目录` → `pwd`，RSS < 200MB（不加载模型），退出码 0
- **AC-25 参数固定**：`df` 必须带 `-h`、`ps` 必须带 `aux` 等，参数来自表内字面量
- **AC-26 高危不兜底**：`rm`（L3）不因兜底被当成"默认参数"执行，仍走确认门
- **AC-27 表外不猜**：`wc`/`grep`/`du` 等即使认出也不执行
- **AC-28 无候选不猜**：完全无关的句子仍然"无法理解"
- **AC-29 来源可区分**：`NlSource` 三种来源，审计/调试不再混为一谈

## 5. 最小设计与触碰模块

| 文件 | 改动 |
|---|---|
| `src/libnlc/decision_cmd.c/.h` | 新增：兜底判定 + 只读默认参数表 + 安全边界 |

| `src/nlsh/dispatch.c` | `parse_smart()` 插入决策层（规则 → 决策 → 常驻 → 本地） |
| `src/libnlc/nlc_api.h` | `NlSource` 增 `NL_SOURCE_DECISION` |

| `scripts/verify_exec.sh` | AC-14 换掉失效前提；新增 AC-15（兜底 pwd 不加载模型 + 高危不兜底） |

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 兜底"猜错工具"执行了别的只读命令 | 参数固定、只读、L1；错了也只是打印了另一份只读信息，不产生写副作用 |
| 默认参数过时（如 `ps aux` 在某些系统无 `aux`） | 只是多打印错误，不影响安全；表小、易审 |
| 词典膨胀导致误配 | 只影响候选排序，不改变"只兜底 L1 + 表内工具"的硬边界 |
