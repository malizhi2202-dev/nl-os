# REVIEW — decision-fallback

压缩路径的 `6-review`：功能轮 + 质量/安全轮。

## 1. 功能轮

| 项 | 结论 | 证据 |
|---|---|---|
| 规则未命中的常见问句能执行 | ✅ | `显示当前工作目录` → `pwd`（11ms），另 6 句同类 |
| 不加载模型 | ✅ | `--no-model` 下全部生效；RSS 19MB（AC-15a） |
| 认不出就如实拒绝 | ✅ | "写首诗""从日志挑错误" 仍返回"无法理解" |
| 与既有链路的顺序正确 | ✅ | 规则 → 决策 → 常驻 → 本地；决策命中时后面两级根本不被调用 |

## 2. 质量与安全轮

| # | 项 | 结论 |
|---|---|---|
| Q1 | 兜底会不会执行用户没说的东西 | ⚠️ 会"补全参数"，但**只补只读语义的固定参数**（`df -h` 而不是 `df`），且只限 L1 工具；写/删/改一律不兜底 |
| Q2 | 参数注入面 | ✅ 零：参数全部是 `READ_DEFAULTS` 里的字面量，输入和模型都不参与拼接 |
| Q3 | 是否借此放宽权限 | ✅ 没有。`ss`/`netstat` 在 `capability_perm_map.h` 里未登记 = L4，仍不放行；网络查看改用已登记的 L1 `lsof` |
| Q4 | 高危命令是否绕过确认门 | ✅ `rm`（L3）实测仍弹确认并因 EOF 取消，探针目录未被删（AC-15c + TEST §3） |
| Q5 | 表外工具会不会"无参数调用"挂住终端 | ✅ 不做；`grep`/`du`/`cat` 需参数的一律跳过（AC-27 / 单测第 4 项） |
| Q6 | 词典扩充会不会把不相关的句子硬配上 | ⚠️ 会配错工具，但最坏后果是**执行了另一条只读命令**（无写副作用）；且分数阈值 8 挡住了零散词 |
| Q7 | 来源是否可区分 | ✅ `NlSource` 增 `NL_SOURCE_DECISION`，审计/调试可分辨规则/模型/决策 |

## 3. 排查中修正的判断

| # | 现象 | 处理 |
|---|---|---|
| B1 | 想用注册表的 `effect == READ` 当"只读"依据 | 查了真实注册表：扫描器把**所有**能力标成 `effect: delete`（缺省从严），该依据不成立 → 改为"权限表 L1 + 默认参数表"双重白名单 |
| B2 | 想放行 `ss`（端口查看） | `ss` 在权限表里未登记 = L4。不放宽权限策略，改用 L1 的 `lsof -i -P -n` |
| B3 | `AC-14` 断言变红 | 不是测试坏了，是**前提变了**（这句不再加载模型）。换输入 + 新增 AC-15 锁新行为，而不是把阈值改松 |
| B4 | 两个候选句子其实到不了模型层 | 复杂度预算层先拒（`替代步骤：cli:ls…`）→ 换成真到模型层的句子，并在 TEST 里记下这两个反例 |

## 4. 残余风险

1. 兜底只覆盖"无参数只读查询"，需要路径参数的说法仍走 20s 模型或如实拒绝。
2. 默认参数是跨发行版的折衷（`ps aux` 等），个别系统可能输出不符预期——不影响安全。
3. 词典仍是人工维护的有限集，新说法不一定被认出（漏救而非误执行）。
