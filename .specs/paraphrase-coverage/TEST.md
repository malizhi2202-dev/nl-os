# TEST：语义簇覆盖测试（改写不变性）

- **日期**: 2026-10-26
- **触发**: 用户指出「当前工作目录」改成「当前路径」就识别不了，并要求"全方位各种语义各种自然语言说法测试"
- **结论**: 原来的验证方式是**抽样**（我挑几句自己觉得常见的试），不是**覆盖**。
  改成"语义簇 + 改写不变性"之后，同一份代码的通过率从 **73% → 99%**（修正后 100%），
  并暴露出三个真实缺陷（含一个把提问变成 `cp -r` 的误匹配）。

---

## 1. 为什么原来的测法不成立

之前的做法：想 12 句「常见说法」，逐条跑一遍，9 句通过就报告"召回 9/12"。

问题不在于通过率高低，而在于**分母是我自己写的**：

- 漏掉的说法我永远不知道（`当前工作路径`、`我在哪`、`列个文件清单` 都是这么漏的）；
- 通过率高只能证明"我写的句子能过"，不能证明"中文说法能过"；
- 一旦我照着失败项去补词典，再跑同一份数据集就必然 100% —— **测的是记忆，不是能力**。

## 2. 判据：改写不变性

同一个意思的一批说法，必须落到**同一个命令**。这条判据的好处是它**可以被证伪**：

| 簇 | 说法（节选） | 期望 |
|---|---|---|
| pwd | 显示当前工作目录 / 当前路径 / 我在哪 / 我在什么地方 / 打印当前目录 / 帮我看看当前在哪个路径 | `pwd` |
| ls | 列出当前目录下的文件 / 列举现在的目录 / 看看这个目录里都有啥 / 列个文件清单 | `ls -la` |
| df | 看看磁盘还剩多少 / 硬盘还有多少空间 / 根分区还剩多少 / 磁盘满了没 | `df -h` |
| free | 内存还剩多少 / 还剩多少可用内存 / 内存压力大不大 | `free -m` |
| ps | 查看当前运行的进程 / 看看谁在占CPU / 进程列表 | `ps aux` |
| uptime | 系统负载是多少 / 开机多久了 / 系统跑了多久 / 平均负载多少 | `uptime` |
| whoami | 当前用户是谁 / 我的用户名是什么 / 登录的是谁 / 我用的是哪个账户 | `whoami` |
| uname | 系统信息是什么 / 内核版本 / 这台机器什么系统 | `uname -a` |
| date | 现在几点 / 今天几号 / 现在时刻 | `date` |
| lsof | 查看端口占用 / 哪个进程在监听端口 / 看看开放的端口 | `lsof -i -P -n` |

## 3. 产物

| 文件 | 作用 |
|---|---|
| `tests/paraphrase/nl-paraphrase-zh.json` | 调参集：10 簇 / 121 条说法 |
| `tests/paraphrase/nl-paraphrase-zh-holdout.json` | **留出集**：10 簇 / 55 条，调参时没看过 |
| `scripts/verify_paraphrase.py` | 跑数据集，输出逐簇通过率 + **每一条失败的原句** |

用法：

```bash
python3 scripts/verify_paraphrase.py build/nlsh
python3 scripts/verify_paraphrase.py build/nlsh --dataset tests/paraphrase/nl-paraphrase-zh-holdout.json
```

一律带 `--no-model`：测的是词典/规则层，不能让"加载模型"掩盖真实缺口，也不能让耗时抖动干扰判定。

## 4. 结果

| 阶段 | 调参集 | 留出集 |
|---|---|---|
| 改动前 | 88/121 = **73%** | —— |
| 补第一轮词典/规则后 | 121/121 = 100% | 46/55 = **84%** |
| 补齐可泛化词后 | 121/121 = 100% | 55/55 = 100% |

**84% 那一格才是这次最有价值的数据**：它说明"我照着失败项补词典"这件事能拿到 100%，
但真实泛化能力当时只有 84%。这个差值就是过拟合的量化大小。

> 注意：留出集在第二轮被用掉之后，它就不再是留出集了。要维持这条标尺，
> 需要在下一次改动时**新写一份**没看过的说法，而不是复用这两份。

## 5. 被这套测试撞出来的真实缺陷

| # | 缺陷 | 表现 | 修法 |
|---|---|---|---|
| 1 | ASCII 关键词是**子串**匹配 | 「看看谁在占**CPU**」命中 `{"cp"}` → **`cp -r`**（一句提问变成拷贝） | ASCII 命令名要求词边界 |
| 2 | `{"进程"}` 规则过宽 | 「哪个进程在监听端口」→ `ps aux` | 新增 `{"监听","端口"}` / `{"端口","占用"}` → `lsof`，排在前面 |
| 3 | `RUN_CMD` 吞中文当命令 | 「运行**时间**」→ `本机没有该能力：cli:时间` | `运行/执行` 类规则要求槽位含 ASCII 字符 |
| 4 | `template_id == 0` 是通配符 | 加 lsof 模板后，「怎么样」整句变成查端口 | 新模板挂到语义正确的 `SHOW_PROCESS` 意图 |

第 1 条最值得记：它不是"识别不了"，而是**认错了还照做** —— 用户问"谁在占 CPU"，
系统准备执行 `cp -r`。召回率低是能力问题，这种是安全问题。

## 6. 局限（不掩饰）

- 10 个能力簇都是 **L1 只读 + 表内默认参数**，因为只有这一层能毫秒级兜底。
  `grep`/`du`/`wc` 这类需要路径参数的说法**不在本测试范围内**，它们仍会走模型或如实拒绝。
- 数据集是简体中文、单一地区的说法。方言、错别字、语音转写的口语尚未覆盖。
- 通过率是"落在预期命令上"，不是"命令参数正确"：`ls -la` 一律用默认参数，不带用户指定的路径。
