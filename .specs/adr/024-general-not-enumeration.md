# ADR-024：通用性从哪来 —— 语义认能力、结构抽参数、权限表当权威

- **状态**: 已采纳
- **日期**: 2026-10-26
- **触发**: 用户连问三句
  - 「解析wwww.baidu.com这个域名的dns」→ 无法理解
  - 「网卡信息」/「网卡」→ 无法理解
  - **「不能我说一些你补充一些啊 这不就成了穷举了吗 没有通用的处理吗 模型层理解不了吗」**

---

## 1. 先承认问题：加规则是穷举

第一轮我的做法是：用户报两句，我就加两条规则 + 两条模板。**这是错的**，
而且它不是"覆盖不全"，是**方法错**：

- 规则是"整句形态"的匹配。用户换一个语序、加一个"帮我"、换一个同义词，规则就不命中。
- 于是每多一种说法就要多一条规则，规则库无限膨胀，而**命中率永远等于"我之前碰巧见过多少种说法"**。
- 更糟的是它掩盖了真正的问题：这些句子本来就不该由规则来决定。

用户问的"模型层理解不了吗"必须分开回答，因为 NL-OS 里有**两个**模型层，当时**两个都没在干活**：

| 层 | 它做什么 | 当时为什么帮不上忙 |
|---|---|---|
| 经典模型层（`nl_parse` → `nl_intent_extract`） | 把句子分类成 13 个 intent + 抽实体 | ① 输出空间只有 13 个 intent，答 `other` 就等于"没有能力"；② **即使答对了 intent，实体也被丢掉**（见 §4），只能落到该 intent 的第一张模板上 |
| 类型化决策层（`decision` / `decision_model`，ADR-013/015） | 候选收缩 + GBNF 受约束 Choice，从**本机真实能力**里选一个 | 只被 `nlsh --eval` 用到，**没接进解析链**；而且候选来源之一（注册表）在用户机器上是空的或过期的（见 §5） |

所以"模型层理解不了"不是模型不会理解，而是：
**理解结果没有出口，出口那一侧的能力目录还是空的/过期的。**

## 2. 结论：三类信号分层，各管一件事

```
                     ┌────────────── 识别"在问什么" ──────────────┐
NL 句子 ── 规则层（整句形态，毫秒级缓存）
        └─ 决策层（语义提示词 → 候选能力；结构判别 → 定夺）
                └─ 模型层（候选内受约束选择 / intent+实体）
                     └────────── 补齐"参数是什么" ──────────────┘
                         结构化抽取（域名按形状、路径按存在性、字面量参数）
```

- **规则层**：保持存在，但定位改成**高频说法的快速缓存**，不再是覆盖手段。
- **决策层**：识别"这句话在问哪一类东西"，从注册表里取真实能力；
  参数只接受两类：**审查过的字面量**（`ip -br addr`）和**按形状校验过的抽取结果**（域名）。
- **模型层**：允许在候选集内做受约束选择；它的实体**必须**参与模板选择（§4）。

关键的一条：**"有没有域名"是结构性判别，不能写进关键词规则。**
「我的 IP 是多少」和「baidu.com 的 IP 是多少」句式几乎一样，区别只在句中有没有一个
合法域名。用关键词规则表达它，只能在其中一半上判错 —— 所以这类判断只能做成
"句中有合法域名 → 问的是远端名字（dig）；否则 → 问的是本机（ip）"。

## 3. 结构性参数抽取：域名的两道关

`dig` 的域名是模板里**唯一的自由文本参数**，因此：

1. **形状抽取**（`nl_extract_domain`）：允许与中文粘连（`解析www.baidu.com这个域名` 里
   域名两端都没有空格，按"关键词后第一个词"取会得到垃圾）。
2. **合规校验**（`nl_domain_check`，`path_safety.c`）：只接受 `[A-Za-z0-9.-]`、标签 1..63、
   顶级域纯字母且 ≥2、总长 ≤253、标签不以 `-` 开头/结尾。
   这一步挡的是 `dig +short -f /etc/passwd` 这类**参数当选项**的注入 —— execvp 不经 shell，
   但选项注入不需要 shell。

抽不到 / 校验不过 → **这条不成立**，退回"无法理解"，绝不生成半条命令
（`{"解析"} + 无域名` 曾差点变成 `dig +short`）。

## 4. 模板选择：从"第一张"改成"槽位能填满的最具体那张"

旧语义：`template_id == 0` 就是"该 intent 的第一张模板"。规则层用它没问题（规则点名的 id 就是答案），
但**模型层用它等于把理解扔掉**：模型说 `list_dir + location=/var/log`，生成出来仍是裸 `ls -la`。

新语义（`template_fill.c: pick_template`）：

1. 在"所有槽位都能填上"的模板里挑**字面槽位最多**的（最具体）；
2. 没有可填满的，退到**不需要任何槽位**的通用模板；
3. 连通用模板都没有 → 返回失败（宁可如实说"无法理解"）；
4. `intent == OTHER` 不参与自动选择（否则 `template_id==0` 的泛规则会静默拿到一张命令模板，
   历史上「怎么样」就是这样变成 `lsof` 的）；
5. **提供了 domain 槽位但不合法 → 直接失败**，不"退到通用模板"（否则「解析 -f xx」会变成 `ip -br addr`）。

## 5. 权限表是权威，注册表只是缓存

`capability_perm_map.h` 把 `ip`/`dig` 登记成 L1 之后，用户机器上它们**仍然是 L4** ——
因为注册表是**扫描时落盘的快照**，而 `--scan` 只"新增"、从不刷新已有条目的结论。
于是决策层按"L4 不进候选"把它们全部过滤掉，通用层在用户机器上等于不存在。

修法：装载注册表时，对 `source == "scan"` 的条目**按权限表重新取值**；
`source != "scan"`（人工 `--allow`）保持原样，不被表覆盖。

同时：注册表为空（首次运行）时，`nlsh` 自己扫一次 PATH 并落盘。
**通用层必须开箱可用**，不能要求用户先知道 `nlsh --scan` 这个命令。

## 6. 为什么 `ip`/`dig` 可以是 L1（以及它凭什么算安全）

这两个二进制本身能写：`ip link set … down`、`dig -f <任意文件>`。
只按"二进制名"登记成 L1 是**不成立的**，所以补一道**按命令形态**的闸门
（`exec.c: nl_exec_form_allowed`，在 `nl_exec_execute` fork 之前）：

| 受控二进制 | 允许的形态 | 匹配方式 |
|---|---|---|
| `ip` | `ip -br addr` | **整条完全一致**（`ip -br addr add …` 这种"前缀对、后面改配置"只有全串比对才拦得住） |
| `dig` | `dig +short <域名>` | 固定前缀 + **恰好一个**通过 `nl_domain_check` 的参数 |

其它形态一律拒绝，fail-closed。这道闸门只管 NL 生成的命令；用户在 shell 里手打
`ip link set …` 属于原始命令快路径，不归这里管（那是用户自己在合法使用 shell）。

## 7. 证据：留出集，跑一次就作废

改完机制后连跑三批**没参与调参**的说法（每批都写"跑完即作废"）：

| 批次 | 说法数 | 通过 | 失败 | 修的是哪一类问题（类级，不是补句子） |
|---|---|---|---|---|
| A | 35 | 34 (97%) | 「我电脑的IP是多少」 | 词典匹配**区分大小写**：`IP` 认不出提示词 `ip` → 改成大小写不敏感 |
| B | 23 | 20 (87%) | 「本机现在连在哪个网段」；「帮我查 example.org 的IP」；「cloudflare.com 指向哪个IP」 | ① 1-2 字虚词提示词（`在哪`）撞车 → 换成带语境的短语；② 域名的**判别力不足**（与提示词累加打平）→ 提到 45 分 |
| C | 19 | 19 (100%) | — | — |

同时回归：主调参集 121/121、`ctest` 全绿、`verify_exec.sh`、`verify_hook.sh`。

**注意 A→B→C 的数字不是"进步曲线"**，而是"每批都暴露了不同的一类缺陷"。
如果没有留出集，这三类缺陷都只会表现为"用户下次又报一句"。

## 7.5 后续自查里又逮到的两处（都写进了代码注释）

- **文件名被当成域名**：`把 /home/x/README.md 的前 20 行给我看看` 曾经解析成
  `dig +short README.md`（`md` 是合法 TLD 形态）。两处修正：
  ① `nl_extract_domain` 跳过前面紧跟 `/` 的 ASCII 串（路径里的那一段是文件名）；
  ② 域名判别还需要**证据**：句子里有 `域名/解析/dns/指向`，或 TLD 在常见表里。
  常见表不是"枚举说法"，TLD 是有限公开、与"怎么说这句话"无关的集合；表外 TLD 只表示
  "不下这个结论"，交给下一层。
- **上下文窗口被 few-shot 撑爆**：本次给模型加了两个示例，prompt 涨到 ~500 token，
  而 `n_ctx` 是 512 —— prompt 塞得进去，**却没有位置生成**，`llama_decode` 报
  `failed to find a memory slot for batch of size 1`，整句退化成"无法理解"。
  改 `n_ctx=2048`（0.5B/2 KV heads 的 KV 开销约 12KB/token ≈ 25MB）+ 生成时按 `pos < n_ctx` 停。

## 8. 边界：什么还没解决

1. **能力目录只覆盖单能力、只读、无参数或单参数**。复合句（`把 error.log 里含 timeout 的行找出来`）
   仍然要靠模型 + 受约束解码，这条链还没进解析链（ADR-022 记录过两个候选路线）。
2. **提示词词典仍然是词典**。它比"整句规则"小一到两个数量级（现在 ~120 条词，不是 120 条句子），
   但新词仍然要人写。真正的泛化要靠候选收缩 + 受约束 Choice 里的模型那一半，
   目前它只在 `--eval` 里跑。
3. **`ip -br addr` 回答不了"网关/DNS 服务器"**（那是 `ip route` / `resolv.conf`）。
   这类需要另一个审查过的形态，不在本次范围。
