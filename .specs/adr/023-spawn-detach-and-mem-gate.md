# ADR-023：后台进程必须双 fork；加载模型前必须过资源闸门

- **状态**: 已采纳
- **日期**: 2026-10-26
- **触发**: 用户报告「本来响应很快，现在输入自然语言到出现结果特别慢」
- **结论**: 两个独立缺陷，都是"在别人的机器上才会犯"的那类

---

## 1. 事故现场

用户终端里一条自然语言输入，卡了 2 分 21 秒没有返回：

```
234520  4528KB   02:21  nlsh -c 列举现在的目录      ← 状态 S，wchan=do_wait
234521 275360KB  29.6%  nlsh --serve --socket ...   ← 它的子进程，wchan=do_poll
```

`nlsh -c` 卡在 `wait()` 里，它等的**不是**中间进程，而是 exec 之后变成常驻守护进程的那个子进程。

## 2. 根因一：单 fork + waitpid(守护进程)

`spawn_daemon()` 原来的实现：

```c
pid_t pid = fork();
if (pid != 0) { if (pid > 0) waitpid(pid, NULL, 0); return; }   /* ← 等的是守护进程本身 */
setsid();
execl(exe, "nlsh", "--serve", "--socket", path, NULL);           /* 这个进程活多久，就卡多久 */
```

**守护进程活多久，用户的终端就卡多久。** 而且 `waitpid` 没有超时，所以是无限挂起，不是"慢"。

### 为什么一直没被发现

因为之前所有验证都是「我先手动 `nlsh --serve &` 起好，再测客户端」——
`ensure_running()` 的探测分支（`connect_once` 成功就直接返回）把 `spawn` 分支整个跳过了。
**这条分支从来没被真正走到过。**

### 修法

双 fork：中间进程 `setsid()` 后立刻 `_exit(0)`，父进程的 `waitpid` 只等这一层，毫秒级返回；守护进程是孙子进程，与调用方彻底无关。

回归测试 `tests/unit/spawn_detached_test.c` 直接测"返回得多快"：
`nl_spawn_detached("/bin/sleep", {"sleep","2"})` 必须在 500ms 内返回。
旧实现在这里会整整等 2 秒 —— 这个断言的存在意义就是让"单 fork + waitpid"再也活不过 CI。

## 3. 根因二：加载模型前不看可用内存

同一时刻机器状态：`MemAvailable 657MB`，而模型文件 409MiB、实测 RSS 677–815MB。

加载它 = 把整台 8GB 机器推进内存回收（该机 swap 为 0）。用户感受到的不只是这条命令慢，
而是**整个桌面/终端一起卡**。

### 修法

`src/libnlc/resource_gate.{h,c}`：

| 判定 | 规则 |
|---|---|
| 需求 | `文件大小 × 2`（实测 RSS/文件 ≈ 1.6–1.9，取 2 留余量） |
| 余量 | 必须为其它进程留出 `NL_MODEL_HEADROOM_MB = 512` |
| 通过条件 | `avail - headroom >= need`（用减法，避免加法溢出成负数被误判为够用） |
| 读数失败 | 一律拒绝（fail-closed） |
| 逃生口 | `NL_MODEL_MEM_FORCE=1` 跳过 |

拒绝加载时**不清空**模型路径 —— 内存释放后下一次请求自动恢复；
错误信息里给出 need / avail / 余量三个数，而不是只说"失败"。

位置在 `ensure_model()`，是客户端与守护进程共用的唯一加载入口，所以两边同时受保护。

## 4. 附带修掉的三个召回/误匹配缺陷

| 缺陷 | 表现 | 修法 |
|---|---|---|
| ASCII 关键词子串匹配 | 「看看谁在占**CPU**」命中 `{"cp"}` → `cp -r`（一句提问变成拷贝） | ASCII 命令名要求词边界（`tests` 里的 CPU 用例锁住） |
| `{"进程"}` 过宽 | 「哪个进程在监听**端口**」→ `ps aux` | 新增 `{"监听","端口"}` / `{"端口","占用"}` → `lsof`，排在 `{"进程"}` 之前 |
| `RUN_CMD` 吃掉中文 | 「运行**时间**」→ `本机没有该能力：cli:时间` | `运行/执行` 类规则要求槽位含 ASCII 字母数字，否则丢弃该命中继续匹配 |

以及一个**陷阱**：`template_id == 0` 的语义是"该 intent 的第一个模板"。给 `NL_INTENT_OTHER`
新增第一个模板，会静默改变规则 122（`{"怎么"} → OTHER, tmpl 0`）的行为 ——
「怎么样」一度整句变成查端口。新模板因此挂到 `NL_INTENT_SHOW_PROCESS`，
并在模板表里写明这条约束。

## 5. 代价与遗留

- 内存紧时模型路径**完全不工作**（只降级到规则/决策层）。这是有意的取舍：
  宁可一条命令不理解，也不拿整机响应性去换。
- `--decide` 诊断路径仍是 eager 加载（已知并接受）。
- 单线程守护进程在推理期间仍会排队后续请求（20s 量级），但已经不会挂死客户端。
