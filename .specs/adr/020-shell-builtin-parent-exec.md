# ADR-020 · shell 内建命令由父 shell 执行（`__NL_CD__` 指令通道）

- 状态：已采纳
- 日期：2026-10-25
- 相关：ADR-019（统一确认门）、ADR-021（常驻解析进程）、change `nl-shell-runtime`

## 背景

`nlsh` 只在子进程里 `fork/execvp` 执行命令。`cd` 是 **shell 内建**（不是 PATH 里的二进制），
所以：

1. 能力注册表里没有 `cli:cd`（扫描器只扫二进制），`进入 /tmp 目录` 会被判"本机没有该能力"；
2. 即使绕过检查，子进程 chdir 对**父 shell 没有任何影响**——说"已执行"是骗人的。

同时 bash 把 `command_not_found_handle` 放在**子 shell** 里跑（实测：
handler 内 `cd /tmp` 后父 shell 的 `PWD` 不变），所以钩子里直接 `cd` 也不行。

## 决策

1. **`cd` 视为永远可用的内建能力**：能力检查里 `nl_shell_builtin_is(argv0)` 为真时跳过注册表，
   cap_id 记作 `shell:cd`（与 `cli:` 命名空间区分）。
2. **执行改为"指令通道"**：`nlsh` 不 `fork`，而是把目标目录写成一行
   `__NL_CD__ <dir>` 追加到 `$NL_SHELL_DIRECTIVE` 指向的文件（由钩子传入）。
3. **由主 shell 应用**：钩子把 `_nl_hook_apply_directive` 挂进 `PROMPT_COMMAND`（主 shell，
   每次提示符前执行），只认 `__NL_CD__ ` 前缀，执行 `cd -- "$dir"`。
4. **不 eval**：跨进程传递的只有一段**路径文本**，不是可执行命令。即使指令被篡改，
   最坏结果是 `cd` 到别的目录——不构成代码执行。
5. **诚实失败**：没有指令通道（独立 `nlsh -c`）、目标不是目录、`HOME` 缺失时，都返回非 0 并说明原因，
   绝不打印"✅ 已切换目录"。

## 后果

- `进入 /tmp 目录`、`切换到上级目录` 在终端里真正生效（实测提示符变成 `/tmp`、`pwd` 输出 `/tmp`）。
- 顺带修掉一个**死模板**：`cd ..`（template 901）此前没有任何规则能选到，
  `切换到上级目录` 会被 83 号规则吃成 `cd 上级目录`。新增 87/88/89 三条规则（须排在 83/84/85 之前）。
- 内建命令的生效时机是**下一个提示符之前**，因此非交互场景（`bash -c` 串多条）不会生效——
  这是 bash 钩子机制的边界，不是本方案的缺陷。

## 备选与否决

| 方案 | 否决理由 |
|---|---|
| 钩子里直接 `cd` | handler 在子 shell，无效（已实测） |
| 钩子 `eval "$(nlsh --print)"` | 等于把模型输出当命令执行，绕过确认门与审计 |
| 让 `nlsh` 自己 `chdir` | 只影响 nlsh 进程自己的子进程，仍改不了你的 shell |
| 注册 `cli:cd` 到能力表并伪造 `path` | 注册表语义是"可执行二进制"，塞假路径会污染扫描与权限映射 |
