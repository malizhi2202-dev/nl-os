# ADR-013: 类型化决策层（Choice / Score / Noul）替代 Agent Loop

- **状态**: accepted
- **日期**: 2026-10-25
- **关联**: `ADR-001`（四层管线）、`ADR-008`（推翻其 Agent Loop）、`ADR-012`（候选来源）

## Context

ADR-008 预留了 Planner/Executor/Observer 的 Agent Loop。外部核查（Jev 的 System One 接口）显示：软件需要的不是"生成计划"，而是**有限答案空间内的类型化判断**——Choice（选一个）、Score（打分）、Noul（是/否）。

关键工程约束（本轮专家讨论得出）：
- 若把 1000 个能力 ID 全部写成 GBNF 字面量，语法体积与解码阻塞开销不可接受 → **必须先收缩候选集**
- 小模型输出 JSON 的合法性不可靠，而"输出不合法就重试"在端侧会吃掉延迟预算
- 安全关卡若依赖模型判断，可被提示注入绕过

## Decision

### 两阶段：候选收缩（无模型）→ 类型化判断（模型）

```
输入 NL
  └─▶ 候选收缩（规则/词典，≤1ms）：关键词命中 + 槽位正则 + 能力名近似 → top-K（K=8）
        └─ K==0 且复杂度超阈值 → refused（走规则预算，不调模型）
        └─ K≥1 → 进模型
  └─▶ Choice（约束解码）：只在 K 个能力 ID + "<refuse>" 中选一个，输出 ≤16 token
  └─▶ Noul（规则优先）：是否需要确认 / 是否命中保护路径
  └─▶ 模板填充（既有）→ 执行
```

### 三个原语的边界（安全定案）

| 原语 | 由谁产生 | 权限影响 |
|---|---|---|
| **Choice** | 模型（GBNF 约束） | **只能从候选集里选，不能新增能力**；选中后仍走既有 L1–L4 判定 |
| **Score** | **规则计算，不调模型** | 只用于复杂度预算与自动化档位；不改变权限等级 |
| **Noul** | 模型给"建议确认"信号，**规则给最终判定** | **模型不得提升权限**：`deny` 永远由规则层/`nl-perm` 决定；模型只能"多要求一次确认"，不能"少要求一次" |

### 约束解码

- 用 llama.cpp 内置 GBNF（`llama_sampler_init_grammar`），不引入外部约束解码库
- 语法按 K 动态生成：`root ::= ("\"" id1 "\"") | ... | ("<refuse>")`
- 输出不合法（理论不可能，但保留防御）→ **回退规则层，不执行**
- 生成上限 16 token；温度 0（贪心）；单次判断 ≤1.5s

### 降级

- 模型缺失 / 加载失败 / `--no-model` → 决策层整体禁用，走段 1 规则预算；**降级路径本身有测试**
- 阈值（候选数 K、拒绝阈值、确认阈值）全部为配置常量，不允许写死在分支里

## Consequences

- ✅ 输出空间有限 → 结构上不可能"乱解析"（用户第 3 点的可证明形态）
- ✅ 输出 ≤16 token + 贪心 → 端侧延迟可控；无需重试（约束解码保证合法）
- ✅ 模型无法提权，提示注入的影响面被限制在"候选集内选错"，而选错仍被 L1–L4 拦
- ❌ 粗筛质量决定上限：粗筛没把正确能力放进 top-8，模型再强也救不回来（PM 反对意见，见下）
- ❌ 需要为每个能力维护"关键词/槽位"元数据，否则粗筛无从下手
- ❌ GBNF 按 K 动态生成需要在每轮构造语法字符串，需缓存按候选集合的哈希键

## 被否掉的备选

| 备选 | 否掉原因 |
|---|---|
| 沿用 Agent Loop（Planner→Executor→Observer） | 不可审计、不可证明边界；ADR-008 推翻 |
| 端到端生成命令文本 | 违反 ADR-001 D9；生成即自由，安全层被架空 |
| 全量 1000 能力写进 GBNF | 语法体积爆炸 + 解码阻塞，实测不可行 |
| 用外部嵌入模型做语义粗筛 | 新依赖 + 额外内存；OpenWrt 档不可行 |
| 让模型做 Noul 的 deny 判定 | 提示注入可直接绕过安全关卡 |

## 残余风险（记录，不隐藏）

- **粗筛即规则**：如果粗筛靠人工关键词表，会重现"规则覆盖 80%"的老问题，且对同义表达脆弱。缓解：benchmark 必须包含"粗筛失败但模型本可救"的样本，单独统计粗筛命中率；v2 再评估是否需要轻量语义粗筛。
- 中文能力名/槽位元数据需人工标注，翻译质量直接影响粗筛。
