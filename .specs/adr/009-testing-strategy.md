# ADR-009: 五层测试金字塔策略

- **状态**: accepted
- **日期**: 2026-07-01
- **关联决策**: 无（独立测试策略决策）

## Context

NL-OS 是一个安全关键系统（权限分级直接防止数据丢失）。测试需要覆盖从 C 函数到端到端 NL 交互的所有层次。同时，模型推理层的测试不同于传统代码测试——不能用二元 pass/fail，需要用准确率分布。

## Decision

**五层测试金字塔，CI 分层执行**：

| 层 | 名称 | 测试内容 | 执行频率 | 预期耗时 |
|---|---|---|---|---|
| **L1** | 单元测试 | 每个 .c 的公开函数 | 每次 commit (CI) | < 10s |
| **L2** | 组件测试 | 单模块独立测试（规则引擎/路径安全/模板填充） | 每次 commit (CI) | < 30s |
| **L3** | 模型推理测试 | Benchmark 准确率评估（离线） | PR merge 前 | < 5min |
| **L4** | 集成测试 | NL-Shell + 权限守护联调 | PR merge 前 | < 2min |
| **L5** | 端到端测试 | Docker 隔离，真实 NL→命令→执行 | Release 前 | < 10min |

**模型层特殊规则**：
- 不设 pass/fail，设 **acceptable 范围**（准确率 ±2% 内可接受）
- 每次模型/prompt 变更必须跑回归测试（500 条），准确率下降 > 2% → 阻塞
- 对抗性测试（500 条）误操作率必须 = 0（安全硬性要求）

**测试框架**：L1-L2 用 `greatest.h`（header-only C 测试），L3-L5 用 shell 脚本 + Python。

## Consequences

- ✅ L1-L3 在 CI 快速反馈（秒级），L4-L5 在关键节点深度验证
- ✅ 模型层用准确率分布而非二元判定，符合 ML 测试特点
- ✅ 对抗性样本零容忍保证安全
- ❌ Benchmark 建设是前期投入（1000 条标注）
- ❌ L5 端到端测试需要 Docker 环境，CI 配置较复杂
