# REVIEW — nl-shell-runtime

压缩路径的 `6-review`：功能轮 + 质量/安全轮（无 UI）。

## 1. 功能轮

| 项 | 结论 | 证据 |
|---|---|---|
| `cd` 真的改变当前目录 | ✅ | 交互式 `pwd` 输出 `/tmp`，提示符同步变化（AC-10a） |
| 失败不说谎 | ✅ | 无通道/非目录均返回非 0 并解释原因（AC-13a/13c） |
| `cd ..` 可用 | ✅ | `[dry-run] cd ..`（AC-13d），死模板已修 |
| 规则未命中不再每次重付加载 | ⚠️ 部分 | 加载省掉（1.8s/次、780MB 反复分配），但推理 20s 仍是瓶颈（已在 ADR-021 明说） |
| 模型路径不再崩 | ✅ | `rc=134` → 正常返回（AC-23 / TEST §2.4） |

## 2. 质量与安全轮

| # | 项 | 结论 |
|---|---|---|
| Q1 | 指令通道是否引入代码执行面 | ✅ 只传**路径文本**，钩子执行 `cd -- "$dir"`，无 eval；AC-12 用 `touch` 载荷证明一字节未执行 |
| Q2 | 内建能力绕过能力检查是否放宽了权限 | ⚠️ 有意识放宽且收窄到 `cd` 一个：effect=read、不改文件、不可逆风险为零；`export`/`alias` 明确不做 |
| Q3 | 是否覆盖用户的 `PROMPT_COMMAND` | ✅ 前插并保留原值（数组/字符串两种形态）；AC-11a/11b 固定 |
| Q4 | 守护进程 socket 权限 | ✅ 目录 0700、socket 0600、路径在 `$XDG_RUNTIME_DIR`（无则 `/tmp/nl-os-<uid>/`） |
| Q5 | IPC 失败会不会影响命令 | ✅ 三级回退，最坏退到升级前行为（AC-22 / 非 TTY 实测） |
| Q6 | 脚本/测试会不会被偷偷拉起守护进程 | ✅ 只在 stdin 是 TTY 时自动拉起（实测 0 socket / 0 进程） |
| Q7 | 客户端超时是否 > 推理耗时 | ✅ 20s → 120s（否则守卫比干活还短，等于白扔） |
| Q8 | 守护进程单连接阻塞风险 | ✅ accepted socket 设 10s 收发超时，半死客户端拖不住服务端 |
| Q9 | 规则文件顺序依赖 | ⚠️ 87/88/89 必须排在 83/84/85 之前（首个命中胜）；已在注释里写明，AC-13d 固定行为 |

## 3. 本次排查中抓到的真缺陷（不是"顺手改"）

| # | 缺陷 | 怎么被发现 | 修法 |
|---|---|---|---|
| B1 | `command_not_found_handle` 在子 shell 执行 → 钩子里 `cd` 无效 | 端到端 `pwd` 不变，直接实测 handler 内 PWD | 改为指令文件 + `PROMPT_COMMAND` |
| B2 | `cd ..` 模板（901）无任何规则可达，`切换到上级目录` 变成 `cd 上级目录` | 端到端试 `cd ..` | 新增 87/88/89 三条规则 |
| B3 | 模型路径每次 `GGML_ASSERT` abort（按 `n_ctx` 而非 `n_batch` 分块） | 守护进程一请求就 core dump，进而发现**本地也一样崩** | 分块上限用 `llama_n_batch` |
| B4 | 客户端探测连接不关 fd → 守护进程卡在等数据，后续请求全排队 | 首次端到端 60s 超时 | 探测后立即 `close` |
| B5 | `spawn_daemon` 里 `waitpid` 等的是守护进程本身 → 父进程死等 | 首次调用 300s 无输出 | 双 fork，中间进程立即退出 |

> B3 最值得记：**测试断言了"模型加载了"，没断言"解析成功"**，于是一个每次调用都 abort 的路径
> 长期存活。已写进 LESSONS。

## 4. 残余风险

1. 规则未命中的句子仍要 20s 量级（模型层瓶颈），交互上不可接受，需模型/候选集那条线解决。
2. 守护进程常驻最多 1 小时（`--max-idle`）且空闲即卸载，但用户极端情况下可能看到 780MB 常驻。
3. 未在 zsh 上验证，也未做并发压测。
