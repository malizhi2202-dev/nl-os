## 用户故事

- **US-1**：作为刚拿到一台新设备（树莓派 / NAS / 工控机 / 路由器）的集成者，我想让系统自己告诉我这台机器能做什么，以便不用逐条试命令就知道可用能力与权限门槛。
- **US-2**：作为习惯用命令行的开发者，我想直接敲 `ls -la` 或已注册的函数调用包时不经过模型，以便没有任何额外延迟，且行为与原生 shell 一致。
- **US-3**：作为非专业用户，我想用一句中文（"把 downloads 里大于 100M 的视频删掉"）完成操作，以便不用记参数、不用查 man。
- **US-4**：作为谨慎的用户，我想在指令超出系统能力时被明确告知"解析不了"并拿到可执行的替代步骤，以便它不会猜一个错命令把事情搞坏。
- **US-5**：作为安全责任人，我想任何涉及保护路径 / 删除 / 提权的动作都被拦截并留下审计，以便事后能回答"谁在什么时候让它做了什么"。
- **US-6**：作为反复做同一套操作的运维，我想把一次成功的自然语言操作固化成 `.tools`，以便下次断网、没模型也能一模一样地重放。
- **US-7**：作为会手抖的用户，我想撤销刚做过的写/删操作，以便误操作不是终局。
- **US-8**：作为合规/排障人员，我想按时间回放所有 NL→动作记录，以便复现问题或举证。

## 验收准则（AC）

### 段 1 · 能力层

#### AC-1 · 能力自发现产出清单

- **Given** 一台从未跑过本系统的机器
- **When** 执行 `nlsh --scan`
- **Then** 在本地索引路径生成能力清单，每项包含能力 ID、绝对路径、建议权限等级（L1–L4），且全过程**不修改任何系统文件**（可用 `git status` 之外的对比验证：扫描前后 `/etc`、`/usr` 的 mtime 不变）
- **验证方式**: `nlsh --scan && ls -l $XDG_STATE_HOME/nl-os/capabilities.json`；`find /etc /usr -newer /tmp/scan-start-marker`

#### AC-2 · 能力自检三档分类

- **Given** 已生成的能力清单，其中包含存在的（`ls`）、需要特权的（`systemctl`）与不存在的（被手工加入的假能力）
- **When** 执行 `nlsh --scan --self-test`
- **Then** 报告把每项分为 `usable` / `needs-privilege` / `missing` 三档；对 `missing` 不猜测替代
- **验证方式**: `nlsh --scan --self-test | grep -E 'usable|needs-privilege|missing'` 计数与清单一致

#### AC-3 · 快路径不经模型

- **Given** 模型未部署（`NL_MODEL_PATH` 指向不存在路径）
- **When** 执行 `nlsh -c 'ls -la'`
- **Then** 命令被直接执行并输出结果；审计日志记录 `fast_path=true`；不出现"仅规则引擎可用"之外的任何模型加载错误
- **验证方式**: `NL_MODEL_PATH=/nonexistent nlsh -c 'ls -la'` + 检查审计日志字段

#### AC-4 · 能力缺失时明确拒绝而非猜测

- **Given** 能力注册表中不存在 `nginx`（本机未安装）
- **When** 输入「重启 nginx」
- **Then** 输出明确说明"本机没有该能力"，并列出注册表中语义最接近的 3 个能力供选择；**不生成任何命令**
- **验证方式**: `nlsh -c '重启 nginx'`；断言输出不含 `systemctl restart` 且含候选列表

#### AC-5 · 复杂度预算拒绝（段 1 · 规则版）

- **Given** 输入超出注册能力或超出顺序指令模型（例：「每天凌晨三点把所有日志按大小切成 100M 的块并压缩后上传到备份服务器」）
- **When** 提交该输入
- **Then** 返回 `refused`，附：① 超出的具体维度（跨能力数 / 需要条件或循环 / 需要网络 / 需要特权）② 至少一条可执行的替代步骤；**不生成完整命令**
- **验证方式**: `nlsh -c '<该输入>'`；断言退出码非 0、输出含 `refused` 与 `替代`

### 段 2 · 决策层

#### AC-6 · Choice 从注册表选能力

- **Given** 决策层可用（模型 + 约束解码就绪），注册表已加载
- **When** 依次提交 20 条中文指令（含 5 条应被拒绝的）
- **Then** 每条输出一个**注册表中存在的能力 ID** + 概率，无编造能力 ID；对 5 条应拒绝的给出 `refused`
- **验证方式**: `nlsh --eval models/benchmarks/nl-commands-zh.json`；输出表格含 `capability_id` / `probability` / `refused`

#### AC-7 · Noul 执行前关卡三档

- **Given** 已选定能力与参数
- **When** 执行前跑关卡
- **Then** 返回 `allow` / `confirm` / `deny` 之一，且与 L1–L4 权限等级一致（L1→allow、L2→confirm、L3→confirm+二次输入、L4→deny）；`deny` 时说明命中的规则
- **验证方式**: 三条样例（`ls` / `mkdir x` / `rm -rf /etc`）分别断言三档

#### AC-8 · 低置信度不执行

- **Given** Choice 概率低于配置阈值（默认值在 DESIGN 定）
- **When** 概率低于阈值
- **Then** 不执行、不显示待执行命令，改为列出 top-3 候选让用户二选一
- **验证方式**: 用一条故意含糊的输入（如「弄一下那个」）断言输出为候选列表而非命令

#### AC-9 · 决策层不可用时降级

- **Given** 模型缺失或 `--no-model`
- **When** 执行 AC-6 中的同一批指令
- **Then** 系统不崩溃、不卡死；规则层可处理的正常执行，处理不了的走 AC-5 的拒绝路径
- **验证方式**: `nlsh --no-model --eval ...`；断言退出码 0 且无 segfault/超时

#### AC-10 · 约束解码保证输出合法

- **Given** 决策层启用约束解码（llama.cpp 原生 GBNF）
- **When** 跑 AC-6 的 20 条指令 ×3 轮
- **Then** 60 次输出 **100%** 符合 schema（能力 ID 在注册表内、分数在 0–1）；任何一次不合规则自动回退规则层，不执行未验证输出
- **验证方式**: 评测输出附 `schema_violations` 计数字段，必须为 0；回退次数单独计数

### 段 3 · 固化与回滚

#### AC-11 · 固化生成 `.tools`

- **Given** 一次成功执行的多步操作（如「创建 project 目录 → 进入 → 创建 main.c」）
- **When** 执行 `nlsh --freeze <会话或操作>`
- **Then** 生成 `.tools` 文件，含：每步的能力 ID、槽位值、校验和头；重复执行同一操作生成的固化文件内容一致
- **验证方式**: `nlsh --freeze ...` → `cat x.tools`（含 `# @checksum:` 与能力 ID）；两次固化 `diff` 为空

#### AC-12 · 固化后离线无模型重放

- **Given** 已固化的 `.tools`，且断网、`NL_MODEL_PATH` 指向不存在路径
- **When** 执行 `nl-run x.tools`
- **Then** 全部步骤成功执行，跳过模型，输出"来自固化脚本（未使用模型）"
- **验证方式**: `NL_MODEL_PATH=/nonexistent nl-run x.tools`；断言成功且日志含固化标记

#### AC-13 · 固化文件篡改被拒绝

- **Given** 一个合法固化文件，被手工修改其中一条命令
- **When** 执行 `nl-run x.tools`
- **Then** 校验和不匹配 → 拒绝执行并报出哪一步被改，**不执行任何步骤**
- **验证方式**: `sed -i 's/mkdir/touch/' x.tools && nl-run x.tools`；断言退出码非 0 且无副作用

#### AC-14 · L2/L3 操作可撤销

- **Given** 执行一次 L2 写操作（创建目录）与一次 L3 删除操作（删除该目录）
- **When** 执行 `nlsh --undo`（最近一次）
- **Then** 恢复到操作前状态（目录及其内容回来）；`--undo` 对 L1 只读操作返回"无需撤销"
- **验证方式**: 造目录 → 删 → `nlsh --undo` → `test -d`；L1 场景断言提示语

#### AC-15 · 快照敏感路径排除 + 容量上限

- **Given** 一次涉及 `~/.ssh/id_rsa` 的读写操作，以及一个快照目录已超过配置上限的状态
- **When** 触发快照
- **Then** 敏感路径（清单在 DESIGN 定，至少含 `~/.ssh`、`~/.gnupg`、`*.pem`、`*.key`、含 `password/token/secret` 的文件）**不产生快照内容**，仅在审计中记"已跳过"；超上限时按 LRU 淘汰最旧快照且不静默失败
- **验证方式**: 构造上述两个场景，断言快照目录无敏感内容、日志含 `skipped-sensitive`、超限时打印淘汰记录

#### AC-16 · 审计可回放

- **Given** 一段时间内的操作历史
- **When** 执行 `nlsh --audit replay --since <ts>`
- **Then** 按序输出每条：时间、输入原文（脱敏后）、能力 ID、权限等级、是否快路径、决策概率、结果；可导出 JSON Lines
- **验证方式**: 执行若干操作后 `nlsh --audit replay --since ...`；`jq` 校验字段齐全

## 范围切分

### v1（本次必做）

- 段 1：能力自发现 / 自检三档 / 注册表 / 快路径 / 规则版复杂度预算（AC-1~AC-5）
- 段 2：Choice/Score/Noul 三原语 + GBNF 约束解码 + 降级（AC-6~AC-10）
- 段 3：固化 / 离线重放 / 篡改拒绝 / 撤销 / 快照策略 / 审计回放（AC-11~AC-16）

### v2（下一轮考虑，本次不做）

- 能力包插件化（第三方以声明文件注册能力，不改二进制）
- 增量扫描优化（当前只做全量与显式 `--scan`）
- 个人词典（"那份周报" → 路径映射）
- 跨机器能力清单对比（"这台和上次那台差什么"）
- 决策层的 Score 用于自动化档位（当前 Score 只用于复杂度预算）

### out（永远不做）

- Agent Loop / 自主多步规划 / 自主反思
- 模型微调
- 写操作的能力自发现（自动装包、自动建 unit）
- 云端模型调用与静默上传
- GUI / 语音 / 多用户

## 非功能性需求

- **性能（按设备档位，见 ADR-015）**：
  - 首次能力扫描 ≤ 2s（树莓派 4，不含自检）；自检 ≤ 10s
  - 快路径额外开销 ≤ 5ms（对比直接 `exec` 同命令）
  - 决策层单次判断 P95：**A 档 ≤ 150ms / B 档 ≤ 1.5s / C 档 ≤ 1s**
  - 冷启动 ≤ 100ms（模型常驻时的热启动）
- **内存（新增，按档位）**：
  - A 档（RAM ≤ 4GB）：常驻 ≤ 600MB（含模型）/ ≤ 80MB（不含模型）；**禁止依赖 swap 达标**
  - B 档（8–16GB）：常驻 ≤ 2GB（含模型）
  - C 档（≥32GB）：常驻 ≤ 8GB（含模型）
  - 模型加载：冷启动 ≤ 2s（热文件缓存）；**常驻进程热启动 ≤ 100ms**
- **可访问性**：无 GUI，不涉及；终端输出需支持非交互模式（管道安全，参照已修复的 tty 问题）
- **安全**：
  - 能力自发现与自检**只读**
  - 能力执行前 `realpath` 复校 + 白名单目录校验（不信任 PATH 顺序）
  - 固化文件校验和不匹配即拒绝
  - 快照排除敏感路径清单
  - 拒绝/拦截必须留审计，日志中敏感值脱敏
- **兼容性**：Linux x86_64 / ARM64 / musl（OpenWrt）；glibc ≥ 2.28；**无 systemd 环境必须可运行**（能力发现降级为 PATH 扫描）；`.tools` 旧格式继续可执行
- **可观测性**：审计日志结构化（JSON Lines），每条含 `ts / input_hash / capability_id / perm_level / fast_path / probability / result / reason`；导出不包含明文敏感参数
- **体积**：`libnlc.so` + 二进制 ≤ 5MB（不含模型）；能力索引 ≤ 200KB（1000 项）

## 依赖与假设

- 依赖：系统 llama.cpp（已存在，`/usr/local/lib`）；无新增第三方依赖；GBNF 用 llama.cpp 内置 sampler
- 假设：模型可选——决策层可整体禁用而系统仍可用
- 假设：本机有可用的 `PATH` 与基本 coreutils；无 systemd 时能力发现按 PATH 降级
- **未决**：决策层中文准确率无任何基线数据（所有公开基准为英文），AC-6 的通过阈值需在 benchmark 跑完后调整，当前阈值只作初始值

### 通过后生效的强制条件（带入 2-design）

1. **注册表格式先冻结**：含 `format_version` + schema 必填字段，AC-1 验证方式同步改为校验版本与必填字段（架构师条件）
2. **拒绝话术的替代步骤必须可直接复制执行**（用户评测员条件）
3. **索引与快照文件权限 0600**；敏感路径清单设计为可配置项（安全条件）
4. **索引/快照并发互斥策略**必须在 DESIGN 写清（安全条件）
