# CHANGE: NL-OS 能力运行时 —— 端侧机器刚部署就能自己熟悉并安全执行

- **Change ID**: `nl-capability-runtime`
- **创建日期**: 2026-10-25
- **路径建议**: 完整（`REQUIREMENT → DESIGN → TASK → DEV → TEST → REVIEW → INTEGRATION`）
- **状态**: draft
- **确认记录**: 用户明确选择「一次全做」（AN: Phase 1–3 同属本次 change，按内部顺序串行交付，每段独立 verify）

---

## Why（为什么做）

一期 MVP（`nl-os`）已经把"自然语言 → 一条命令"跑通了（四层管线 + L1–L4 权限 + `.tools`），但三个结构性缺口让"端侧机器刚部署就能自己用"不成立：

1. **机器不知道自己有什么能力。** 可执行能力全部硬编码在 `rules_db.h` / `templates_db.h`。换一台机器（NAS 没有 `docker`、路由器没有 `systemctl`、工控机没有 `apt`），这份清单就是错的——用户说"重启 nginx"，系统不知道这台机器上根本没有 nginx。
2. **"解析的度"没有可证明的边界。** 复杂指令目前只有"模型猜"和"规则不命中"两种结果，既不能明确拒绝，也无法解释为什么拒绝。用户要的是：**超出能力就直说解析不了，并给出能做的替代步骤**。
3. **决策被规划错了。** 原 ADR-008 预留了 Planner/Executor/Observer 的 Agent Loop。经外部核查（Jev 的 System One 接口形态），**不需要 Agent Loop**：决策可以收敛成"有限答案空间内的类型化判断"（Choice/Score/Noul），从结构上就不可能乱解析。这条认知必须在 DESIGN 定案，否则会沿错误方向铺代码。

## What（做什么）

一句话：**让机器先知道"我能做什么"，再用类型化判断决定"要不要做、做哪个"，最后把成功的操作固化成可复用脚本。**

三段同属本次 change，**按顺序串行交付，每段独立 verify，不允许跨段合并提交**：

### 段 1 · 能力层（零模型依赖）

- **能力自发现**：扫描本机可执行能力（PATH 白名单目录中的二进制、systemd 单元、容器运行时、包管理器、系统信息），产出能力清单
- **能力自检**：只读自检（能否执行 / 退出码），分"可用 / 需特权 / 缺失"三档，**不解析 help 语义**
- **能力注册表**：能力 ID + 建议权限等级（L1–L4）+ 槽位描述，落盘为本地索引，支持增量重扫
- **快路径**：直接输入的传统命令 / C 片段 / 已注册函数调用包**不经模型**直接执行（显式化并纳入审计）
- **复杂度预算（规则版）**：结构化判定（跨几个能力？要循环/条件？要特权？超出注册能力？），超阈值返回"解析不了 + 可执行替代步骤"
- **审计留痕**：能力 ID、权限等级、是否快路径、拒绝原因

### 段 2 · 决策层（类型化判断，替换 Agent Loop）

- 三原语实现：**Choice**（从注册表里选能力）/ **Score**（复杂度与风险打分）/ **Noul**（执行前是/否关卡）
- 模型只输出少数 token 的判断结果，**不生成命令文本**；命令仍由模板填充产出
- 约束解码优先用 **llama.cpp 原生 GBNF grammar sampler**（零新依赖），不引入外部 Rust 组件
- 概率参与控制流：高置信自动执行 / 接近阈值显示命令等确认 / 低于阈值拒绝并给替代
- 决策层不可用时**必须**降级到段 1 的规则版预算（OpenWrt 等无模型设备只走规则）

### 段 3 · 固化与可回滚

- **技能固化**：一次成功的 NL 操作可固化为 `.tools`（记录能力 ID + 槽位），之后不经模型直接执行
- **回滚快照**：L2/L3 操作执行前自动留快照，支持撤销；快照与审计日志同源可回放
- **能力引用**：`.tools` 增加能力引用字段，能力缺失时 fail-fast 而不是猜

## 想法压测（0-change 步骤 1.5）

- **技法**：假设反转 + 逆向 + 类比迁移
- **假设反转**：「必须先有强模型才能自然语言操作系统」→ 反转后成立：**能力清单是确定的，模型只需做排序**，0.5B 够用，甚至无模型也能跑快路径
- **逆向**（怎么做到最糟）：能力清单硬编码 → 换机器全错；解析失败时猜一个命令 → 误删；决策交给模型自由生成计划 → 不可审计。这三条正好对应三段的三个核心设计
- **类比迁移**：Jev 的 State + 类型化问题 + 代码持有政策 → 直接借接口形态（不用它的云服务）
- **压测 6 问结论**：最不需要这个的是"只有一台固定开发机的重度用户"（记命令比说话快）；预算砍一半只保"能力自发现 + 快路径 + Noul 关卡"；最小可验证版本 = 能力清单 + 一次自检报告 + 一次执行前 Noul 拦截

|---|---|

| **ADR-007 模块边界** | 新增项目级模块「能力注册表」（`libnlc/capability_*.c` + 本地索引），接口不得由 `nlsh` 私有持有 |

## 范围排除（这次不做）

- ❌ **Agent Loop / 多步自主规划 / 自主反思** —— 已判定不做（见架构影响声明）
- ❌ **模型微调** —— 保持"永远不做"
- ❌ **写操作的能力自发现**（自动装包、自动建 systemd 单元、自动改配置）—— 只读发现
- ❌ **跨机器能力同步 / 远程执行 / 多机编排**
- ❌ **GUI / 语音 / 多用户** —— 沿用 `nl-os` 的 out 清单
- ❌ **外部约束解码库（llguidance 等）** —— 只用 llama.cpp 内置 GBNF

## 验收线（粗粒度）

1. 新机器首次运行产出一份能力清单 + 自检报告（可用/需特权/缺失三档），全程**零写操作**
2. 20 条中文指令：规则层可覆盖的生成正确命令且 L1–L4 判定正确；覆盖不到的返回"解析不了 + 替代步骤"，**不猜**
3. 危险操作（路径穿越、零宽字符、间接引用保护路径）**0 漏网**，每次拦截有审计记录
4. 决策层能把"模糊指令"落到正确能力上，且在执行前由 Noul 关卡给出"需确认/放行/拒绝"三档之一
5. 一次成功的多步 NL 操作可固化为 `.tools`，固化后**断网 + 无模型**仍能重放成功
6. L2/L3 操作可撤销：执行后能恢复到操作前状态

## 风险与未知

| 风险 | 等级 | 处理 |
|---|---|---|
| **三段耦合，能力 ID 未稳就上决策层/固化 → 返工** | 🔴 高 | 段间强顺序：段 1 的注册表格式冻结后才开段 2；每段有独立 verify 门，禁止跨段合并提交 |
| 能力自发现扫描范围过大导致启动慢 | 🟡 中 | 增量索引 + `--scan` 显式触发 |
| 不同发行版 `--help` 格式差异 | 🟡 中 | 自检只判"能否执行/退出码"，不解析 help 语义（语义留段 2 的模型判断） |
| 能力清单被污染（PATH 恶意同名二进制） | 🔴 高 | 只扫白名单目录 + 记录绝对路径与 inode，不信任 PATH 顺序，执行前 realpath 复校 |
| **OpenWrt 档设备跑不了模型，决策层无法工作** | 🟡 中 | 决策层必须可整体禁用，降级到规则版预算；降级路径本身要有测试 |
| **中文决策准确率未知**（所有公开基准都是英文） | 🔴 高 | 先建中文评测集再谈阈值；阈值必须是可配置常量，不允许写死 |
| 固化脚本被篡改（`.tools` 变攻击载荷） | 🔴 高 | 固化文件带校验和；执行前校验；能力引用必须能在注册表中找到 |
| 快照占用磁盘（端侧存储小） | 🟡 中 | 快照有容量上限 + 自动过期；只对 L2/L3 留快照 |
| 与现有 `rules_db.h` 硬编码清单双份真相 | 🟡 中 | 注册表为唯一真相，规则库只引用能力 ID（2-design 定） |
